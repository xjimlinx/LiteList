# LiteList 跨平台功能契约

`shared/document.schema.json` 是 Windows 原生版与 Plasma Plasmoid 的共同数据边界。
两端可以拥有不同的窗口、配置和通知实现，但不得改变这里定义的业务含义。

## 数据所有权

- `tasks`、`notes`、`goals`、`notifications` 和各自的 `next_*_id` 是可迁移的用户数据。
- `settings` 是平台表现状态。窗口坐标、Plasma 折叠状态、DWM/KDE 模糊参数等不得成为核心功能的前置条件。
- 读取版本 1 后必须规范化为版本 2；未知的未来版本必须拒绝，不能用旧程序覆盖。
- Windows 与 Plasma 都必须能无损读取并重新写出 `goals`、节点 `requires` 和节点 `shape`。

## 目标路线规则

- 最多 100 个大目标，全部大目标合计最多 2000 个小目标。
- 大目标 ID 全局唯一；小目标 ID 在整个文档中全局唯一。
- 小目标只能依赖同一大目标中的已有节点，不能依赖自己，也不能形成循环。
- 没有前置条件的小目标立即解锁；其他小目标必须在全部前置节点完成后解锁。
- 完成状态只能通过明确的完成操作改变，点击或拖动画布本身不触发完成。
- 已有完成节点依赖某前置节点时，该前置节点不能撤回。
- 仍被其他节点依赖的小目标不能删除。
- 非空大目标的全部小目标完成时自动完成；任一节点未完成或没有节点时，大目标不完成。
- 节点形状 `-1` 表示继承平台设置，`0`、`1`、`2` 分别表示圆角、直角、胶囊。

## 一致性验证

`shared/fixtures/goals-v2.json` 是两端共同的黄金数据：

- Rust 单元测试必须完成反序列化、校验、再次序列化及规则检查。
- `tests/store.test.js` 必须读取同一文件并验证节点形状、依赖顺序、层级和变更规则。
- 新增可迁移功能时，应先扩展 schema 与共享夹具，再修改两端领域实现，最后接入各自 UI。
